1. Configuration File Migration

The foundation of any migration. Configuration files define what the AI coding assistant knows about your project and what it's allowed to do.

1.1 CLAUDE.md → AGENTS.md / instructions

Claude CodeOpenCode EquivalentReplacement Strategy
Files: CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md
Loading: Walks directory tree upward, auto-discovers and concatenates all CLAUDE.md files
Imports: @path/to/file.md inline syntax 		Files: AGENTS.md plus any markdown files
Loading: Explicit "instructions" array in opencode.json with glob support
Substitution: {file:path/to/file} for inline file content
  1. Run /init in OpenCode to auto-generate AGENTS.md (reads existing CLAUDE.md, .cursorrules, .windsurfrules)
  2. List all instruction files in opencode.json: 
    {
  "instructions": [
    "AGENTS.md",
    "CONTRIBUTING.md",
    ".cursor/rules/*.md"
  ]
}
  3. For CLAUDE.local.md: create a gitignored AGENTS.local.md and add it to the instructions array, or use ~/.config/opencode/opencode.json
  4. For @imports: list all files explicitly (glob patterns supported)
If your repo already uses AGENTS.md: OpenCode natively uses it. Claude Code reads CLAUDE.md instead. If you're maintaining an AGENTS.md for Cursor or Windsurf, OpenCode picks it up directly — no duplication needed.

1.2 .claude/rules/ Migration

Claude CodeOpenCode EquivalentReplacement Strategy
Directory: .claude/rules/
Scoping: YAML frontmatter with paths: glob patterns — rules auto-load only when Claude touches matching files 		No path-scoped equivalent. All instruction files are loaded globally. OpenCode loads whatever is in the "instructions" array regardless of which file is being edited. Three approaches, pick one:
A. FlattenMerge all rules into AGENTS.md. Accept the context cost of always-loaded instructions. Best for small-to-medium projects.
B. Agent-basedCreate specialized agents per domain (frontend, backend), each loading its own instruction files. Best for monorepos and large projects.
C. Command-basedConvert path-specific rules into custom /commands that users invoke when working in specific areas.
// Agent-based example: opencode.json
{
  "agent": {
    "frontend": {
      "description": "React, TypeScript, CSS",
      "prompt": "{file:./opencode/agents/frontend-prompt.md}",
      "model": "claude-sonnet-4-6"
    }
  }
}

1.4 Auto Memory → Manual Context

Claude CodeOpenCode EquivalentReplacement Strategy
Claude Code automatically saves learnings, preferences, and debugging insights to ~/.claude/projects/<project>/memory/. These accumulate across sessions — Claude "remembers" project conventions and past decisions. No auto memory. OpenCode treats each session independently. All project knowledge must live in instruction files and AGENTS.md.
  1. Export before migrating: Review ~/.claude/projects/<project>/memory/MEMORY.md and extract key conventions, build commands, and debugging patterns
  2. Fold into AGENTS.md: Incorporate valuable learnings as permanent team documentation
  3. Maintain proactively: When the team discovers new patterns or conventions, manually add them to AGENTS.md. Make instruction file updates part of your code review process

2. Skills & Commands

Claude CodeOpenCode EquivalentReplacement Strategy
Skills: .claude/skills/<name>/SKILL.md with YAML frontmatter
Commands: .claude/commands/<name>.md (flat markdown, auto-merged into skills)
Auto-invocation: Claude can automatically load a skill when your task matches its description
Dynamic injection: !`command` shell execution at load time injects output into prompt 		Commands: .opencode/commands/<name>.md or "command" key in opencode.json
Skills: .opencode/skills/ directory
Invocation: /name with $ARGUMENTS placeholder
No auto-invocation, no dynamic injection 		Command migration: 
// Claude Code: .claude/commands/deploy.md
---
description: Deploy the application
disable-model-invocation: true
---
Deploy: 1. Run tests 2. Build 3. Push to $ARGUMENTS

// OpenCode: opencode.json
{ "command": { "deploy": {
  "template": "Deploy:\n1. Run tests\n2. Build\n3. Push to $ARGUMENTS",
  "description": "Deploy the application to a target environment",
  "agent": "build"
} } }
Frontmatter mappings:
description→ "description" in command config
context: fork→ Run in a subagent via "agent" field
allowed-tools→ "tools" in agent definition
model→ "model" in command or agent config
arguments→ $ARGUMENTS, $0, $1 in template
paths→ No equivalent — use agent scoping
!`cmd` injection→ Wrapper scripts that pre-compute context
No auto-invocation. Claude Code can automatically load skills when your task matches the skill's description. OpenCode commands must be invoked manually via /name. If you rely on auto-discovered skills, either invoke them manually or include that knowledge in globally-loaded instruction files.

3. Commands Reference & Advanced Features

3.1 Slash Commands Mapping

Every Claude Code built-in slash command and its OpenCode counterpart.

Claude Code CommandOpenCode EquivalentReplacement Strategy
/help /help Both show available commands. OpenCode's help is context-sensitive based on your config.
/clear Start new session OpenCode has no in-session clear. Press Ctrl+C to interrupt, then start a fresh session from the TUI session list.
/model Edit opencode.json or /connect No mid-session model switching. Set "model" in config or per-agent. Changing the default agent's model requires editing config and restarting.
/plan Tab key Claude Code uses Shift+Tab or /plan. OpenCode toggles plan/build mode with the Tab key in TUI.
/init /init Claude Code generates CLAUDE.md; OpenCode generates AGENTS.md. OpenCode also reads existing CLAUDE.md, .cursorrules, and .windsurfrules to bootstrap.
/login /connect Claude Code logs into Anthropic. OpenCode connects to 75+ providers — select one and enter API credentials.
/plugin Edit opencode.json "plugin" array Claude Code has /plugin install|uninstall|list. OpenCode loads plugins from .opencode/plugins/ or npm packages listed in config — no interactive install command.
/memory No equivalent Claude Code opens the auto-memory editor. OpenCode has no auto-memory — maintain AGENTS.md manually.
/compact Automatic Claude Code triggers context compaction manually. OpenCode manages context windows automatically — no manual trigger needed or available.
/review Natural language: "review this PR" Claude Code's /review triggers the code-review skill. In OpenCode, describe what you want reviewed in natural language.
/security-review Natural language or custom command Ask the agent to "do a security review" or create a custom /security-review command in .opencode/commands/.
/export /share Claude Code exports the conversation. OpenCode's /share uploads the session and copies a shareable link (can be disabled).
/resume TUI session list OpenCode displays previous sessions in the TUI. Select one to resume — no slash command needed.
/cost Provider-dependent Cost visibility depends on the provider — Anthropic and OpenAI show usage; local models cost $0.
/doctor No equivalent Manually check: Node.js version, provider connectivity, and config file validity.
/status No equivalent Check the TUI header for current model and agent in OpenCode.
/stats No equivalent Track usage externally via provider dashboards.
/config Edit opencode.json directly Claude Code opens settings in an editor. OpenCode has no config command — edit files manually.
/agents Agent config in opencode.json Agents are defined in config and listed in the TUI agent picker.
/permissions Edit opencode.json "permission" key Both tools configure permissions through config files. No interactive permission editor in OpenCode.
/context No equivalent Check the "instructions" array in opencode.json to see what's loaded.
/ide IDE extension Claude Code attaches to VS Code / JetBrains. OpenCode offers its own IDE extension.
Custom commands: Recreate any missing Claude Code slash command as an OpenCode custom command in .opencode/commands/<name>.md or via the "command" key in opencode.json, using $ARGUMENTS for dynamic input.

3.2 AgentTeam, UltraThink & Other Advanced Features

Claude Code FeatureOpenCode StatusReplacement Strategy
AgentTeam Not available

Claude Code's AgentTeam (experimental) launches multiple subagents in parallel, coordinates them via a shared task list, and merges results. Agents can spawn other agents and delegate subtasks.

Workarounds:

  • Run multiple OpenCode sessions in separate terminals with different agent configs
  • Use a shared task file (markdown checklist) for coordination between sessions
  • Orchestrate via Makefile, CI pipeline DAG, or custom scripts
  • For complex multi-agent workflows, consider LangChain or CrewAI as an external orchestration layer
UltraThink Partial

Claude Code's UltraThink mode enables extended reasoning with higher thinking token budgets. The model spends more time analyzing before responding.

OpenCode approach: Use models that support extended thinking — Claude Opus 4.7 via Anthropic provider, or OpenAI o-series models. Configure a dedicated agent:

{
  "agent": {
    "deep-thinker": {
      "model": "claude-opus-4-7",
      "description": "Extended reasoning for complex problems",
      "prompt": "{file:./opencode/agents/deep-thinker-prompt.md}"
    }
  }
}

Not all providers expose thinking budget controls. Claude models via Anthropic and OpenAI o-series are your best options.
Plan Mode Available Claude Code uses Shift+Tab / /plan. OpenCode toggles plan/build mode with Tab. Functionally identical.
Context: fork Available Claude Code skills can run in an isolated forked context. OpenCode achieves the same via subagents — each gets a clean context and returns results to the main session.
Dynamic injection (!`cmd`) Not available

Claude Code executes shell commands at skill-load time and injects the output into the prompt.

Workaround: Create a wrapper script that pre-computes context, then reference it:

#!/bin/bash
git log --oneline -20 > /tmp/recent-commits.txt
opencode -p "Review: {file:/tmp/recent-commits.txt}"
Subagent delegation Available Both tools let the main agent spawn subagents. Claude Code has built-in Explore and Plan agents; OpenCode requires custom agents with tool restrictions (e.g., "write": false, "bash": false for Explore-like).
Context compaction Automatic Claude Code offers manual (/compact) and automatic compaction. OpenCode handles it internally — no user control, but also no need to manage it.
Auto memory Not available Claude Code persists learnings across sessions. OpenCode treats each session independently — add conventions to AGENTS.md manually.
Terminal sandbox Not available Claude Code sandboxes Bash at the OS level (macOS Seatbelt, Linux landlock/seccomp). OpenCode has no sandbox — use Docker, VMs, or macOS sandbox profiles externally.
Multi-model routing Available Claude Code routes tasks to different Claude models. OpenCode does this natively per-agent — set "model" on each agent. Plus you can mix providers (Haiku via Anthropic, Opus via Bedrock).
Prompt caching Provider-dependent Claude Code uses Anthropic's prompt caching. In OpenCode, caching depends on the provider — Anthropic models support it; other providers vary.
AgentTeam is the biggest architectural gap. If your workflow depends on coordinated multi-agent work (parallel agents sharing a task list, spawning sub-agents, merging results), there is no direct substitute in OpenCode. Evaluate whether you can break the workflow into sequential steps, run sessions in parallel manually, or use an external orchestration framework.

4. Hooks → OpenCode Equivalents

Claude Code has 24+ lifecycle events with five hook types (command, HTTP, MCP tool, LLM prompt, subagent). OpenCode has no hook infrastructure — but many hook use cases have practical replacements.

Hook Use CaseClaude Code HookReplacement Strategy
Lint / format after edits PostToolUse on Write/Edit runs ESLint, Prettier OpenCode formatters: 
{
  "formatter": {
    "prettier": { "extensions": [".js", ".ts", ".tsx"] },
    "eslint-fix": {
      "command": ["npx", "eslint", "--fix", "$FILE"],
      "extensions": [".js", ".ts", ".tsx"]
    }
  }
}
Supplement with pre-commit hooks (husky, lefthook). $FILE is replaced with the target file path at runtime.
Block dangerous commands PreToolUse exits 2 for rm -rf, sudo, etc. Permission deny patterns: "permission": { "rm *": "deny", "sudo *": "deny" }
System-level: restricted sudo, shell aliases, Docker seccomp profiles
Session start setup SessionStart sets env vars, warms caches, checks deps Wrapper script that runs pre-flight checks before launching opencode
Desktop notifications Notification on idle, auth, permission events External tools: terminal-notifier (macOS), notify-send (Linux), tmux hooks
Prompt validation UserPromptSubmit blocks prompts matching patterns No direct equivalent — rely on team conventions and code review
Post-edit context injection PostToolUse with additionalContext No equivalent — OpenCode doesn't support runtime context injection. Redesign the workflow or use external file watchers
Auto-commit on change PostToolUse runs git add + git commit External file watcher (watchexec) or periodic cron job
Config change detection ConfigChange reloads on file change OpenCode watches opencode.json natively; restart for other config files
Formatters are the closest built-in alternative. They cover the most common hook use case — auto-formatting and linting when files are written. For everything else, you'll need external tooling.

5. Plugins

AspectClaude CodeOpenCode EquivalentReplacement Strategy
Manifest .claude-plugin/plugin.json — name, version, author npm package.json or direct file placement in .opencode/plugins/ Package plugins as npm modules for versioning and distribution
Distribution Marketplace (official + community), git repo, zip npm registry (public or private), git repo, direct file placement Publish to npm or share via git. Reference in opencode.json: "plugin": ["@org/package"]
Loading /plugin install name@marketplace, --plugin-dir Place in .opencode/plugins/ or add npm package to "plugin": ["pkg"] No interactive install — plugins are configured declaratively
Components Skills, agents, hooks, MCP, LSP, monitors, settings, bin/ Skills, agents, commands, tools, MCP Hooks and monitors have no equivalent — replace with external tooling. LSP is built into OpenCode
Namespacing /plugin-name:skill-name — automatic collision prevention No namespace system — command names must be globally unique Use unique command name prefixes (e.g., /myplugin-do-thing). Document naming conventions
Marketplace Centralized discovery and one-click install No centralized marketplace Distribute via npm; document available plugins in team wiki or README
npm-based distribution advantage: OpenCode can load plugins directly from npm — if your team already uses npm for package management, plugin distribution integrates with your existing workflow. Claude Code has no native npm plugin support.

6. MCP Servers

Both tools support the Model Context Protocol. The servers themselves work identically — only configuration syntax differs.

AspectClaude CodeOpenCode EquivalentReplacement Strategy
Config location .mcp.json, ~/.claude.json "mcp" key in opencode.json Translate config syntax (see example below)
Transport: HTTP type: "http" (streamable-http) type: "remote" with URL Rename type and move URL field
Transport: stdio type: "stdio" type: "stdio" Identical — command and args map directly
Transport: SSE Deprecated in Claude Code Not documented Migrate to HTTP (remote) transport before switching
OAuth 2.0 Full OAuth with keychain storage, DCR Not documented Use API-key-based MCP servers. For OAuth-only servers, deploy an authentication proxy
Tool search Deferred loading via tool_reference blocks Not documented Connect fewer MCP servers per session; be selective about exposed tools
Channels MCP servers push messages into sessions Not documented Poll-based MCP tool invocation; external webhook handlers for push events
Elicitation MCP servers request user input mid-task Not documented Use inline prompts in session; pre-configure MCP tool inputs

Config Translation Example

// Claude Code: .mcp.json
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer ${GITHUB_TOKEN}" }
    },
    "local-db": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@bytebase/dbhub", "--dsn", "postgresql://..."]
    }
  }
}

// OpenCode: opencode.json
{
  "mcp": {
    "github": {
      "type": "remote",
      "url": "https://api.githubcopilot.com/mcp/",
      "enabled": true
    },
    "local-db": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@bytebase/dbhub", "--dsn", "postgresql://..."]
    }
  }
}
OAuth gap: If your team uses OAuth-authenticated MCP servers (Sentry, Notion, Slack via MCP), verify whether those servers offer API-key authentication as a fallback. OpenCode does not document MCP OAuth support.

7. Subagents & Agent Teams

Claude CodeOpenCode EquivalentReplacement Strategy
Built-in agents: Explore (read-only research), Plan (architecture design), general-purpose
Custom agents: .claude/agents/<name>.md with tool restrictions, skills, model
Agent Teams: Experimental multi-session coordination with shared task lists — agents spawn sub-agents and delegate work 		Custom agents: .opencode/agents/<name>.md or "agent" key in opencode.json
Config: description, model, prompt, "tools": {"write": false, ...}
No built-in Explore or Plan agents, no Agent Teams 		Agent definition translation: 
# Claude Code: .claude/agents/security-reviewer.md
---
name: security-reviewer
description: Reviews code for OWASP Top 10 vulnerabilities
tools: Read, Grep, Glob
model: claude-sonnet-4-6
---
You are a security reviewer...

// OpenCode: opencode.json
{
  "agent": {
    "security-reviewer": {
      "description": "Reviews code for OWASP Top 10",
      "model": "claude-sonnet-4-6",
      "prompt": "{file:./opencode/agents/security-reviewer.md}",
      "tools": { "write": false, "edit": false, "bash": false }
    }
  }
}
Recreating Explore-like agents: Create a custom agent with "write": false, "bash": false and an appropriate research-oriented system prompt.
Agent teams workaround: Run independent OpenCode sessions in parallel; use a shared markdown task file for coordination. For complex multi-agent workflows, consider external orchestration (LangChain, CrewAI, CI pipeline DAGs).

8. Feature Gap Analysis

Complete list of Claude Code features with no or partial OpenCode equivalent. Use as a quick reference when evaluating whether a specific workflow can be migrated.

Claude Code FeatureOpenCode StatusReplacement Strategy
✗ Hooks system (24+ events, 5 types) No lifecycle hook infrastructure Formatters, pre-commit hooks, wrapper scripts, file watchers
✗ Auto memory No automatic cross-session learning Maintain AGENTS.md manually; make updates part of code review
✗ Dynamic injection (!`cmd`) No shell execution in command templates Wrapper scripts pre-compute context; use {file:...} substitution
✗ Agent teams (multi-session coordination) No multi-session coordination Parallel independent sessions; external orchestration (LangChain, CrewAI)
✗ Explore agent (built-in read-only research) No optimized read-only research subagent Create custom agent with "write": false, "bash": false
✗ Plan agent (built-in architecture planning) No dedicated architecture planning subagent Use OpenCode's Tab-toggle plan mode; create a custom "architect" agent
✗ OS-level sandboxing No filesystem or network sandbox for Bash Docker containers, macOS sandbox profiles, Linux seccomp
✗ MCP channels (push-based events) No push-based event stream from MCP servers Poll-based MCP tool invocation; external webhook handlers
✗ MCP elicitation (server → user dialogs) No MCP server → user input request dialog Inline prompts in session; pre-configure MCP tool inputs
✗ MCP OAuth 2.0 No OAuth flow for MCP server authentication Use API-key-based MCP servers; deploy auth proxy for OAuth-only servers
✗ MCP tool search (deferred loading) No documented deferred tool loading Connect fewer MCP servers per session; be selective
✗ CLAUDE.md directory walking No auto-discovery of parent directory configs Explicitly list all instruction files in opencode.json
✗ Path-scoped rules No rules that auto-load based on file path Agent-based scoping; flatten into global instruction files
✗ Skill auto-invocation Commands are only user-invoked (/name) Invoke commands manually; put always-needed knowledge in instruction files
✗ Plugin namespacing No /plugin:command namespace isolation Use unique command name prefixes; document naming conventions
✗ Plugin marketplaces No centralized plugin discovery and install Distribute via npm; document in team wiki
✗ Native auto-update No background automatic updates brew upgrade, npm update -g, or choco upgrade
✗ Managed MCP exclusive control No managed-mcp.json for locking down MCP Central config prescribes MCP servers; Enterprise plan for enforcement
✗ Fine-grained Bash permission parsing Permissions don't parse compound commands Use exact patterns; restrict to safe command prefixes
✗ Read/Edit path deny rules No gitignore-pattern file access rules OS-level file permissions; containerization
✗ Slack interface No Slack integration for conversational coding Use OpenCode's CLI, TUI, Web, or IDE interfaces
✗ JetBrains IDE extension IDE extension support may differ Evaluate OpenCode's IDE extension; use TUI as fallback
◐ UltraThink (extended reasoning mode) Partial — depends on model support Use Claude Opus 4.7 or OpenAI o-series with thinking budgets via Anthropic/OpenAI providers
